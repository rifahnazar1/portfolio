My AI Development Workflow

How I build software with AI in the loop — deliberate, specification-first, and gated by review and evaluation before anything reaches production.

1

Requirement

I start from the actual problem and the user outcome, not the feature. Getting the "why" precise up front prevents building the wrong thing fast.

2

Specification

I write a short, concrete spec — inputs, outputs, edge cases, and acceptance criteria. This is what makes AI-assisted coding reliable: a clear spec is a better prompt than any clever instruction.

3

Claude Code

I use Claude Code for the larger, multi-file moves — scaffolding, refactors, and changes that need to reason across the whole codebase from the spec.

4

Cursor

For tighter, in-editor iteration I switch to Cursor — quick edits, inline exploration, and staying in the flow while shaping a single file or function.

5

Manual review

I read every line before it lands. AI accelerates writing; it doesn't remove ownership. I'm accountable for what ships, so I review for correctness, clarity and intent.

6

Unit tests

I cover the logic that matters and the edge cases from the spec. Tests lock in behaviour so later AI-assisted changes can't silently regress it.

7

Evaluation

For anything with a model in the loop, unit tests aren't enough. I evaluate behaviour against representative scenarios — including adversarial and low-confidence cases — because reliability comes from evaluation, not prompts alone.

8

Debugging

When something fails I reproduce it from traces and logs, fix the root cause, and add a test or eval case so it can't come back.

9

Production

Shipping is the start of the loop, not the end. Observability — cost, latency and quality — feeds the next requirement.

The through-line: AI writes fast, but reliability comes from specification, review and evaluation. That's the same philosophy behind every project in this portfolio.
