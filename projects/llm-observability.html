LLM Observability Dashboard

Ingest LLM API calls and track cost, latency and usage per app, user and model — with automatic cost estimation, projections, drill-down, a Python SDK and a polished dashboard.

Overview

Teams shipping LLM features quickly lose visibility into what those features cost and how they behave. This project is a self-hostable observability service: an ingest API receives an event per LLM call, and a dashboard turns those events into cost, latency and usage insight — including projected monthly spend and P95 latency for SLO monitoring. A drop-in Python SDK makes instrumenting an existing app a one-liner.

Architecture

An app instruments each LLM call via the SDK; events flow to the FastAPI ingest endpoints, are persisted with SQLAlchemy, and are aggregated on read for the dashboard.

Engineering decisions

Estimate cost when the caller can't

cost_usd is optional on every event — if omitted, it's derived from a built-in pricing table keyed by model. Instrumentation stays trivial (just send tokens) and cost still shows up on the dashboard.

Aggregate on read, keep ingest cheap

Ingest just validates and stores. Summaries, comparisons, projections and P95 are computed in the query layer, so writing an event is fast and the analytics can evolve without a migration.

Buffered SDK mode for hot paths

The SDK offers single, buffered (auto-flush at 10) and an OpenAI response helper — so high-throughput callers can batch without changing how they think about tracking.

Auth and privacy where it matters

An optional API key protects only the ingest endpoints; reads stay open for the dashboard. Prompt/completion previews can be redacted at the DB layer via a single env flag for privacy-sensitive deployments.

Testing

The service ships with a pytest suite covering ingestion, cost estimation, and the aggregation endpoints, plus a seed script that generates realistic sample data so the dashboard can be exercised end-to-end.

  • Cost estimation verified against the pricing table for each supported model.
  • Aggregation endpoints (usage, summary, projection, P95) tested on seeded data.
  • Ingest validated for both single and batch payloads, with and without an API key.

Future improvements

  • Swap SQLite for Postgres/ClickHouse to scale ingest and time-series queries.
  • Add alerting on cost/latency thresholds (Slack/webhook).
  • Native tracing spans to tie multi-step agent runs to their per-call costs.
  • Quality/eval metrics alongside cost and latency for a fuller observability picture.
